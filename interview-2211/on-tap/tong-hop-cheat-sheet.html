Cheat sheet B1 · Java core & Spring

B1 · mở trang →

HashMap

  • index = (h ^ h>>>16) & (n−1); n là lũy thừa 2
  • Va chạm: list → cây đỏ-đen khi ≥ 8 và mảng ≥ 64
  • Resize ×2 khi size > cap × 0,75; phần tử giữ chỗ hoặc dời +oldCap
  • Không thread-safe: mất ghi, size sai

ConcurrentHashMap

  • Đọc không khóa; bucket rỗng: CAS; bucket có node: synchronized node đầu
  • Atomic: merge, compute, computeIfAbsent, putIfAbsent
  • Không null; size() chỉ ước lượng

equals / hashCode

  • equals bằng → hashCode bằng
  • Thiếu hashCode: Set chứa trùng, Map không tìm thấy
  • Key bất biến; record

Exception

  • Unchecked + mã lỗi + @RestControllerAdvice
  • Không nuốt lỗi; log một lần; không lộ stack trace

Stream

  • Không nhanh hơn for; đọc dễ hơn
  • parallelStream: CPU-bound, dữ liệu lớn, ArrayList; không I/O (ForkJoin pool chung)

Spring

  • Singleton dùng chung → không giữ state theo request
  • Constructor injection: final, dễ test, lộ class quá to
  • @Transactional: proxy; self-invocation và private không có tác dụng
  • Rollback mặc định: RuntimeException + Error
  • REQUIRES_NEW để ghi log lỗi độc lập
  • Không gọi HTTP trong transaction: cạn pool, không rollback được bên ngoài

Cheat sheet B2 · Concurrency & JVM

B2 · mở trang →

Công cụ đồng bộ

  • volatile: thấy, không atomic (count++ sai)
  • synchronized: thấy + atomic, đơn giản
  • ReentrantLock: tryLock(timeout), ngắt được, Condition
  • Atomic*/CAS: một biến; LongAdder khi đếm nóng
  • Nhiều instance → khóa ở DB/Redis, không ở JVM

Deadlock

  • 4 điều kiện; phá vòng chờ bằng thứ tự khóa nhất quán
  • jstack: “Found one Java-level deadlock”; PG: 40P01
  • lock_timeout, tryLock; không giữ khóa khi gọi I/O

Thread pool

  • core → queue → max → reject
  • Không dùng newFixedThreadPool (queue vô hạn → OOM)
  • Queue có giới hạn, CallerRunsPolicy, đặt tên thread

Kích thước

  • Little: L = λ × W (200 rps × 50 ms = 10)
  • CPU: ≈ số core; I/O: core × (1 + chờ/tính)
  • Pool DB: core DB × 2 + đĩa; nhân số instance

JMM

  • happens-before: unlock→lock, ghi→đọc volatile, start, join
  • DCL cần volatile vì gán tham chiếu có thể trước constructor

JVM & GC

  • Heap / stack / metaspace / direct
  • HeapDumpOnOutOfMemoryError + MAT dominator tree
  • Thủ phạm: static map, listener, ThreadLocal, nạp cả bảng
  • G1: region, young → mark → mixed; Full GC = xấu
  • Heap sau GC đi lên bậc thang = rò rỉ
  • Virtual thread: I/O-bound, giới hạn bằng Semaphore

Cheat sheet B3 · SQL & PostgreSQL

B3 · mở trang →

Index

  • B-tree sắp xếp, O(log n), lá nối nhau
  • (a,b,c): leftmost prefix; range ở b chặn c
  • Bằng trước, khoảng sau; partial index cho trạng thái ít giá trị
  • Mất index: hàm trên cột, LIKE '%x', ép kiểu, thống kê cũ

EXPLAIN (ANALYZE, BUFFERS)

  • Đọc từ trong ra
  • Cờ đỏ: ước lượng lệch, Rows Removed lớn, Nested Loop loops lớn, sort ra đĩa
  • pg_stat_statements, auto_explain

Isolation (PG)

  • Mặc định Read Committed; không có dirty read
  • RR: snapshot cả giao dịch, lỗi 40001 khi đụng
  • Write skew: chỉ Serializable hoặc khóa rõ

MVCC

  • UPDATE = bản mới + dead tuple
  • VACUUM: dọn, visibility map, chống wraparound
  • Bloat do giao dịch mở lâu; idle_in_transaction_session_timeout

Khóa

  • FOR UPDATE: tranh chấp cao
  • SKIP LOCKED: hàng đợi worker
  • Version: tranh chấp thấp, đọc ghi cách xa
  • Conditional update: quy tắc trong WHERE

Phân trang, N+1, thiết kế

  • Keyset (created_at,id) < + index; không nhảy trang
  • N+1 → JOIN hoặc = ANY(:ids)
  • Phi chuẩn hóa đường đọc nóng; một nguồn sự thật + đối soát

Migration không downtime

  • Thêm cột null → ghi kép → backfill theo lô → đối soát → đổi đọc → xóa cũ
  • CONCURRENTLY; NOT VALID rồi VALIDATE (NOT NULL qua CHECK); lock_timeout ngắn

Pool

  • core DB × 2 + đĩa; nhân số instance; PgBouncer
  • connectionTimeout ngắn; theo dõi pending

Cheat sheet B4 · Redis & cache

B4 · mở trang →

Kiểu dữ liệu

  • String: cache, INCR, SET NX PX
  • Hash: object; ZSet: xếp hạng, cửa sổ trượt
  • Set: unique; HyperLogLog: đếm duy nhất 12 KB; Bitmap: điểm danh

Đơn luồng

  • RAM + epoll + không khóa
  • Cấm: KEYS (dùng SCAN), big key, Lua dài; DEL → UNLINK
  • SLOWLOG, --bigkeys

Mẫu cache

  • Cache-aside (mặc định): DB rồi xóa cache
  • Write-through: cache luôn mới, ghi chậm
  • Write-behind: nhanh, có rủi ro mất

3 sự cố

  • Penetration: key không có → cache rỗng, Bloom filter
  • Breakdown: 1 key nóng hết hạn → khóa dựng lại, làm mới sớm
  • Avalanche: nhiều key cùng lúc → TTL jitter, HA, breaker

Lệch cache

  • Xóa, không cập nhật; DB trước, xóa sau
  • Double delete, TTL, xóa qua CDC/outbox
  • Hot key: Caffeine cục bộ, nhân bản key, tách bộ đếm

HA & khóa

  • RDB + AOF everysec; Sentinel (failover) vs Cluster (16.384 slot)
  • Redis chết: cache fail-open + breaker; rate limit tùy mục đích
  • Khóa: SET NX PX + token, nhả bằng Lua
  • Hết hạn khi GC pause → fencing token, kiểm tra ở DB

NoSQL

  • Từ mẫu truy vấn; Cassandra cho ghi lớn theo khóa
  • Mất JOIN, giao dịch; nhất quán cuối cùng

Cheat sheet B5 · REST, HTTP, mạng

B5 · mở trang →

REST

  • Danh từ số nhiều; hành động → tài nguyên con
  • GET/PUT/DELETE idempotent; POST không
  • 409 xung đột, 422 nghiệp vụ, 429 + Retry-After
  • Lỗi: {code, message, traceId}; 4xx không retry

Idempotency-Key

  • Unique (user, key) + status + lưu response
  • COMPLETED → trả lại; PROCESSING → 409; hash khác → 422
  • TTL 24h; lớp cuối ở DB

HTTP

  • 1.1: keep-alive, 1 request/kết nối
  • 2: multiplexing, HPACK, còn HOL của TCP
  • 3: QUIC/UDP, hết HOL, 0-RTT, đổi mạng không đứt
  • Kết nối mới: TCP 1 RTT + TLS 1.3 1 RTT

TCP

  • TIME_WAIT: bên chủ động đóng, cạn cổng → pool
  • CLOSE_WAIT: mình quên close → lỗi code
  • ulimit -n, somaxconn; ss -s

Auth

  • Session: thu hồi dễ, có trạng thái
  • JWT: stateless, khó thu hồi → access ngắn + refresh xoay vòng + blocklist
  • OAuth2 = ủy quyền; OIDC = đăng nhập

OWASP API

  • SQLi: #{} không ${}
  • IDOR: kiểm quyền từng tài nguyên
  • Mass assignment, lộ dữ liệu → DTO
  • Rate limit, SSRF, secret ngoài code

Cheat sheet B6 · Hệ phân tán

B6 · mở trang →

Kiến trúc

  • Tách khi: nhiều đội, tải khác biệt, ranh giới rõ
  • Modular monolith trước; tránh distributed monolith
  • CAP khi phân mảnh; PACELC lúc bình thường: trễ vs nhất quán
  • Tiền/tồn kho: C; like/feed: A

Chống lỗi

  • Timeout theo p99 + deadline
  • Retry chỉ idempotent, 1 tầng, budget, backoff + jitter
  • Breaker: đóng → mở → nửa mở; bulkhead: pool riêng
  • 3 tầng × 3 retry = 27 lần

Kafka

  • Thứ tự chỉ trong partition; key = thực thể
  • Consumer ≤ partition; acks=all, idempotence
  • At-least-once + consumer idempotent (event_id unique)
  • Lag: hot partition, poison → DLQ, max.poll, cooperative rebalance

Nhất quán

  • Dual write sai → outbox cùng transaction + relay/CDC
  • Saga: bù trừ nghiệp vụ, idempotent; orchestration vs choreography
  • 2PC: chặn, chỉ phạm vi hẹp

Mở rộng & vận hành

  • Shard key: đều, một shard cho truy vấn chính, ổn định
  • Consistent hashing + virtual node; shard logic cố định
  • Rate limit: token bucket (burst), sliding window; Redis + Lua; 429
  • Liveness (restart) vs readiness (rút khỏi LB); graceful shutdown
  • RED/USE, p99 từ histogram, SLO + burn rate, correlation id

Cheat sheet B7 · DSA

B7 · mở trang →

Độ phức tạp

  • HashMap O(1) TB; TreeMap O(log n) có thứ tự
  • PriorityQueue: offer/poll O(log n), peek O(1)
  • ArrayList get O(1), chèn giữa O(n); LinkedList hiếm khi tốt hơn → ArrayDeque

Chọn cấu trúc

  • LRU: LinkedHashMap(accessOrder) / map + list đôi
  • Top-K: min-heap K → O(n log K)
  • Rate limiter: deque thời điểm
  • Interval: sort + quét; chồng lịch: TreeMap floor/ceiling
  • Duy nhất: HashSet / HyperLogLog
  • Window max: deque đơn điệu

Mẫu tư duy

  • Cần tra nhanh → HashMap
  • Mảng đã sắp → hai con trỏ / binary search
  • Khoảng liên tiếp → sliding window
  • K lớn/nhỏ nhất → heap
  • Đường ngắn nhất không trọng số → BFS

Nói to

  • Làm rõ → brute force → tối ưu → code → chạy tay → biên → độ phức tạp
  • Biên: rỗng, 1 phần tử, trùng, âm, tràn số

Cheat sheet D1 · Sự cố

D1 · mở trang →

Thứ tự luôn dùng

  • Cầm máu (rollback, flag, giới hạn tải) → dữ liệu → giả thuyết → kiểm chứng → sửa gốc → ngăn tái diễn

p99 tăng, CPU thấp

  • Thread đang chờ: khóa, pool, dependency, GC
  • jstack ×3, trace APM, diff bản deploy, canary

Pool cạn, DB rảnh

  • idle in transaction, HTTP trong transaction, rò rỉ, query chậm
  • Hikari active/pending, leakDetectionThreshold

Kafka lag

  • Một partition: hot key/poison; tất cả: chậm hoặc rebalance
  • DLQ, gom lô, max.poll, alert theo thời gian trễ

Bộ nhớ, cache

  • Heap sau GC tăng bậc thang = rò rỉ → heap dump + MAT
  • static map, listener, ThreadLocal
  • Cache về 0: lạnh hoặc đổi key → khóa dựng lại, warm-up, rolling

Dữ liệu

  • Trùng thông báo: at-least-once + unique (noti, device) + collapse key
  • Bài biến mất: replica lag → read-your-writes, sticky
  • Tồn lệch: khóa job, idempotent, sửa bằng bút toán điều chỉnh

Hạ tầng

  • Đĩa đầy: log, WAL do replication slot chết; alert 80% + tốc độ
  • Retry storm: backoff + jitter, budget, half-open, ramp-up, load shedding
  • Postmortem: timeline, 5 Whys, action có chủ + hạn, không đổ lỗi
