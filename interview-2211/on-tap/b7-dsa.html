B7 · Cấu trúc dữ liệu và giải thuật

Vì sao LinkedList hiếm khi nhanh hơn: về lý thuyết chèn giữa là O(1), nhưng phải đi tới vị trí đó mất O(n) trước. Mỗi node là một object riêng (thêm khoảng 24 byte và hai con trỏ), nằm rải rác trong bộ nhớ nên cache CPU kém; ArrayList dời phần tử bằng System.arraycopy liền khối nên rất nhanh. Cần hàng đợi hai đầu thì dùng ArrayDeque, không dùng LinkedList.

Phân tán thì Top-K làm thế nào?

Mỗi node tính top-K cục bộ (hoặc dùng Count-Min Sketch), gộp ở node tổng. Với bảng xếp hạng thời gian thực thì dùng Redis ZSet.

Khung nói to cho mọi bài:

  1. Nhắc lại đề, hỏi ràng buộc: kích thước n, có số âm không, có trùng không, input rỗng?
  2. Nêu brute force và độ phức tạp.

Two Sum · HashMap lưu giá trị → chỉ số. O(n).

Map<Integer,Integer> seen = new HashMap<>();
for (int i = 0; i < a.length; i++) {
  Integer j = seen.get(target - a[i]);
  if (j != null) return new int[]{j, i};
  seen.put(a[i], i);
}

Valid parentheses · Stack (ArrayDeque). O(n).

Deque<Character> st = new ArrayDeque<>();
for (char c : s.toCharArray()) {
  if (c=='(') st.push(')'); else if (c=='[') st.push(']'); else if (c=='{') st.push('}');
  else if (st.isEmpty() || st.pop() != c) return false;
}
return st.isEmpty();

Merge intervals · sắp xếp theo start, nối nếu chồng. O(n log n).

Arrays.sort(iv, (x, y) -> Integer.compare(x[0], y[0]));
List<int[]> out = new ArrayList<>();
for (int[] cur : iv) {
  if (out.isEmpty() || out.get(out.size()-1)[1] < cur[0]) out.add(cur);
  else out.get(out.size()-1)[1] = Math.max(out.get(out.size()-1)[1], cur[1]);
}

LRU cache · LinkedHashMap. O(1).

class LRU<K,V> extends LinkedHashMap<K,V> {
  private final int cap;
  LRU(int cap) { super(16, 0.75f, true); this.cap = cap; }
  protected boolean removeEldestEntry(Map.Entry<K,V> e) { return size() > cap; }
}

Người phỏng vấn có thể yêu cầu tự viết HashMap + danh sách đôi với node đầu/cuối giả.

Top K frequent · đếm + min-heap K. O(n log k).

Map<Integer,Integer> cnt = new HashMap<>();
for (int x : nums) cnt.merge(x, 1, Integer::sum);
PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.comparingInt(cnt::get));
for (int x : cnt.keySet()) { pq.offer(x); if (pq.size() > k) pq.poll(); }

Sliding window maximum · deque chỉ số, giá trị giảm dần. O(n).

Deque<Integer> dq = new ArrayDeque<>();
for (int i = 0; i < a.length; i++) {
  while (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();
  while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();
  dq.offerLast(i);
  if (i >= k - 1) res[i - k + 1] = a[dq.peekFirst()];
}

Binary search biến thể · tìm vị trí đầu tiên thỏa điều kiện. O(log n).

int lo = 0, hi = n;            // [lo, hi)
while (lo < hi) {
  int mid = lo + (hi - lo) / 2; // tránh tràn số
  if (ok(mid)) hi = mid; else lo = mid + 1;
}
return lo;                      // n nếu không có

Dùng cho: lower bound, mảng xoay, tìm đáp án nhỏ nhất thỏa (tốc độ ăn chuối, sức chứa tàu).

BFS / DFS trên đồ thị · BFS cho đường ngắn nhất không trọng số, DFS cho đếm thành phần. O(V + E).

Deque<Integer> q = new ArrayDeque<>(List.of(src));
boolean[] seen = new boolean[n]; seen[src] = true;
while (!q.isEmpty()) {
  int u = q.poll();
  for (int v : adj.get(u)) if (!seen[v]) { seen[v] = true; q.offer(v); }
}

Lưới 2D (số đảo): DFS/BFS 4 hướng, đánh dấu đã thăm.

Nếu bị hỏi tiếp

Em không nghĩ ra lời giải tối ưu thì làm sao?

Nói brute force và code nó cho đúng trước, nói rõ chỗ chậm, rồi thử các hướng: HashMap đổi bộ nhớ lấy thời gian, sắp xếp, hai con trỏ, heap. Người phỏng vấn thường gợi ý nếu thấy bạn suy nghĩ có hệ thống.

mid = (lo + hi) / 2 có vấn đề gì?

Tràn số khi lo + hi vượt Integer.MAX_VALUE. Dùng lo + (hi - lo) / 2 hoặc (lo + hi) >>> 1.

Cheat sheet B7 · DSA

B7

Độ phức tạp

  • HashMap O(1) TB; TreeMap O(log n) có thứ tự
  • PriorityQueue: offer/poll O(log n), peek O(1)
  • ArrayList get O(1), chèn giữa O(n); LinkedList hiếm khi tốt hơn → ArrayDeque

Chọn cấu trúc

  • LRU: LinkedHashMap(accessOrder) / map + list đôi
  • Top-K: min-heap K → O(n log K)
  • Rate limiter: deque thời điểm
  • Interval: sort + quét; chồng lịch: TreeMap floor/ceiling
  • Duy nhất: HashSet / HyperLogLog
  • Window max: deque đơn điệu

Mẫu tư duy

  • Cần tra nhanh → HashMap
  • Mảng đã sắp → hai con trỏ / binary search
  • Khoảng liên tiếp → sliding window
  • K lớn/nhỏ nhất → heap
  • Đường ngắn nhất không trọng số → BFS

Nói to

  • Làm rõ → brute force → tối ưu → code → chạy tay → biên → độ phức tạp
  • Biên: rỗng, 1 phần tử, trùng, âm, tràn số
